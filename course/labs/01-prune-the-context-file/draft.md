# AGENTS.md

## Project Overview

`myapp` is a Python web service that provides reporting and data export functionality to
customers. It is organised as a layered application with a clear separation between the HTTP
handling layer, the business logic layer and the data access layer. The service supports both
synchronous and asynchronous export flows, the latter backed by a background job queue, and
exposes a small number of HTTP endpoints for triggering and polling those exports.

The codebase is small but production-shaped, and is intended to be readable. New contributors
should be able to find their way around it within an hour.

## Development Setup

1. Clone the repository.
2. Create a virtual environment: `python3 -m venv .venv`
3. Activate it: `source .venv/bin/activate`
4. Install the development dependencies: `pip install -r requirements-dev.txt`
5. Install the pre-commit hooks: `pre-commit install`
6. Verify your setup by running the test suite: `pytest -q`

If any of the above fails, check that you are on a supported Python version and that your
virtual environment is activated. Most setup problems are one of those two things.

## Coding Standards

- Follow PEP 8. The formatter enforces most of it, so do not argue about formatting in review.
- Use type hints everywhere. The codebase is mypy-strict and new code must not regress that.
- Prefer explicit over implicit. Prefer readable over clever.
- Keep functions small and focused on a single responsibility.
- Use descriptive variable names. Avoid single-letter names except in comprehensions.
- Write docstrings for public functions and classes.
- Keep line length under 100 characters.
- Import order is enforced by ruff's isort rules; do not hand-sort imports.
- Relative imports are banned repository-wide.

## Architecture

The application follows a layered architecture:

- **API layer** (`myapp.api`) handles HTTP requests and responses.
- **Service layer** (`myapp.service`) holds business logic.
- **Repository layer** (`myapp.repo`) handles data access.
- **Tasks** (`myapp.tasks`) run work outside the request cycle.

Each layer may only depend on the layer below it. The API layer must never reach directly into
the repository layer; it goes through the service layer. This is a **code review convention**
and reviewers are asked to watch for violations.

Background tasks sit outside the layer ordering. They may call into the service layer, but must
never call back up into the API layer.

## Testing

- We always write tests for new functionality.
- Aim for high coverage. The team targets 90% or better.
- Tests live in `tests/` and mirror the package structure.
- Use pytest fixtures for shared setup.
- Prefer integration tests over heavily mocked unit tests where practical.
- Run the full suite before pushing.

## Python Best Practices

- Use `pathlib` rather than `os.path`.
- Use f-strings rather than `%` formatting or `.format()`.
- Use context managers for anything that needs cleanup.
- Prefer dataclasses to dictionaries for structured data.
- Avoid mutable default arguments.
- Use `enumerate` rather than manual index counters.
- Catch specific exceptions, never bare `except:`.

## Gotchas

- `myapp/repo/analytics.py` and `myapp/repo/exports/queries.py` both select on the account
  column, and the analytics table is smaller. An agent asked to "export the account's rows"
  will often reach for analytics, produce a confident CSV, and get the row count wrong.
- The export fixtures are slow. A full `pytest -q` takes longer than you expect and that is
  the fixtures, not your change.

## Git Workflow

- Branch from `main`, named `<type>/<ticket>-<slug>`.
- Write commit messages in the imperative mood.
- Reference the ticket identifier in the commit body.
- Rebase rather than merge when updating a branch.
- Squash trivial fixup commits before requesting review.
- Open a pull request and request review from a code owner.

## Deployment

The service is deployed from `main` after CI passes. Deployment is handled by the platform
team's pipeline and there is nothing to run locally.
