WHY CRITERION 2 IS TWO COMMITS, AND WHY THE SECOND ONE IS ONE LINE

91ca80 makes the endpoint return 403 with an upgrade URL. It passes both tests anyone
would write for criterion 2, and it is wrong in the way this whole ticket is about: it
calls the shared helper without saying what to do when entitlement is unknown, so it
inherits default=True and hands the feature to every account mid-signup.

b7e4d2 adds `default=False` at that call site. One argument, its own commit, named for
the criterion it completes.

Splitting it was deliberate. The two commits are the before and after of the blocking
finding, and a reviewer reading criterion by criterion sees the fix land as a separate
reviewable thing rather than buried inside the feature that needed it.

The first commit is the spec and the touchpoints, before any implementation. PR #341 was
merged before PR #342 was opened.


THE FOUR FILES

  tooling/myapp/api/entitlements/views.py           criterion 2
  tooling/myapp/service/entitlements/service.py     criterion 1
  tooling/myapp/repo/entitlements/queries.py        criterion 1
  tooling/tests/test_entitlements.py                both

Compare that against 04-touchpoints.md, which declared five paths. Four were changed. The
fifth — tooling/myapp/service/billing/upgrade.py:44 — was NOT, because the spec put it out of
scope and answer 4 said explicitly not to change its behaviour.

Which is the difference from the export ticket, and the reason this second chain earns
its place.
There the untouched fifth file broke anyway, because a shared function's behaviour moved
underneath it. Here the fifth file does not break, because the fix went to the call site
instead of to the shared signature — and it did not break on purpose, as the result of a
question somebody asked before writing code.

Same shape of hazard. Opposite outcome. The difference is entirely upstream of the diff.


WHAT THIS ARTIFACT CANNOT DO

`git diff --stat` against a touchpoints list catches a file appearing where the spec did
not expect one. Nothing here would have caught the alternative history in which the shared
default was flipped: that change touches only files inside the plan, the diff stays clean,
and the upgrade page changes for every mid-signup account.

The deterministic scope check would have reported four files, all inside touchpoints, and
been correct and useless. What caught it was question 4, which is not a tool.
